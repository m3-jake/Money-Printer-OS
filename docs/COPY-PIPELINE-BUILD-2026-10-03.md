# Missing-primary protection

Post-install provider stalls exposed another cadence issue: mirror sports discovery walks many sequential provider families and copy discovery/execution may chain multiple individually timed reads. Both bots now use separate async contexts for polling and settlement with a 12-second work allowance and four-second hard provider waits, including response bodies and transports that ignore AbortSignal. Expired underlying reads remain coalesced until drained, and their late results are rejected rather than applied as current fills. Retained mirror SELL intents execute before sports discovery; any newly discovered SELL is supervised once in that tick, preserving partial-depth accounting. Pending work remains durable for the next cadence. Snapshots report the limits and draining-read count. Tests cover signal-ignoring fetch/body, no duplicate underlying request, no late fill, and exit supervision before a stalled sports board. Targeted suite: 104 passed.

Installation review reproduced an HTTP event-loop stall: processing 299 preserved historical copy intents with no network delayed a zero-delay timer by 2,089 ms through per-event synchronous whole-book fsync. Discovery now commits one bounded observation batch before any handoff or follower execution; admission-only decisions commit and yield every 25 events. Actual execution attempts continue committing individually. The real BotTape now explicitly supports leader-selection and execution-receipt streams, fixing the production-only unknown-stream errors missed by tape-null fixtures. A real-tape catch-up test verifies receipt retention and timer service; targeted suite now passes 102 tests.

Copy and mirror books now retain an immutable `.initialized.json` companion after successful initial persistence or validated legacy reads. A missing primary with that marker (or a verified checkpoint) exposes unknown balances and recovery-required status; reads and writes never recreate capital automatically. This also blocks deletion during an active process. Marker presence is evidence only, not an automatic restoration source. The existing explicit `RESET BOT` operation remains the sole way to authorize a fresh generation, and reset now waits for independent settlement work too. Legacy primary bytes and cash are preserved when adding the marker. Targeted copy/bots/audit/runtime/settlement/scoreboard verification: 101 tests passed, including missing-primary restart, live deletion, explicit reset, and legacy grandfather cases.
