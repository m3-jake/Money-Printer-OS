# Copy pipeline implementation batch — October 3, 2026

Implemented and targeted-tested source; installation/runtime verification belongs to the paired release ledger.

- Preserved incumbent books, realized losses and sticky incumbent drawdown pause. Corrupt copy books expose unknown balances and remain untouched. Explicit resets archive prior bytes.
- Added `mpo.copy-event.v1` observations and durable execution intents, bounded overlapping public pagination (100 × 3 pages), age/processing-latency policy, retryable provider/fee/depth waits, and source identity deduplication. Incomplete catch-up remains visible rather than implying complete holdings history.
- Discovery runs before optional settlement. `run({ settlement: false })` and guarded `runSettlement()` permit separate fast and maintenance schedules. Four concurrent source reads maximum per copy book. Shared public discovery cache coalesces reads for five seconds; follower books, marks and authoritative resolutions bypass it.
- Evicted/rotated leaders free entry discovery slots and retain exit supervision. Source SELL quantities use an explicitly labeled entry-relative ratio; legacy unknown holdings use full-exit policy. Partial depth produces partial sells with allocated basis/fees, persistent remaining exit quantity, unique close-slice IDs and `parentPositionId`. Copies use current follower depth and venue fees, never the leader's earlier execution price.
- Separate immutable, hash-bound $25 exploratory books support direct, liquidity-scaled, deterministic random-eligible and no-trade policies. Parent integration chooses cohort paths and schedules. Aggressive exploration does not alter incumbent qualification or erase its pause. Other proposed policies need trustworthy category/independence/opposite-contract data before executable admission.
- New market classification uses actual category/sports type/tags before explicitly labeled title inference. Existing historical unknown rows are not invented or rewritten. Attribution counts distinct positions/events and includes holding horizons.
- Kalshi mirror captures wallet, source trade/time, selection snapshot, decision/quote time, exact-size fills and matching identity. Sports source polls every minute, uses bounded pagination and prioritizes observed target overlap. A refresh can preview one historical page for up to 24 sports wallets to rank overlap, without copying those historical trades. Exact GAME_WINNER mapping is retained; unsupported rules/families remain unsupported. Exit books do not wait for the sports metadata board.
- Tape streams: existing `polycopy-trades`; new `polycopy-leaders`, `polycopy-receipts`. Receipts include source identity, first observation, decision, quote, fills, costs and exits/resolution. These are prospective records and do not manufacture missing dated historical snapshots.

Persistent per-event exit requests now carry separate remaining quantities. Also retained source-to-mirror handoff retries after a follower entry already filled, preserved exit requests under full queue pressure, and recovered receipt journaling after an exposure had committed just before restart. Terminal identity compaction preserves a finalized cursor floor; out-of-order events inside the retained horizon remain eligible, pending exits remain durable, and ancient compacted source events cannot be replayed.

Unknown historical timing does not contribute. Quote receipt time is recorded independently of metadata completion.
